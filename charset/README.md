# charset — 文字コード・改行コードの変換

`editorleaf/charset` は、ファイルのバイト列とバッファの内容を相互に変換するパッケージです。
バッファ側の扱い（`editbuffer/fileconv.go`）と ESC x コマンド（`excommand_encoding.go`）も、このドキュメントで説明します。

## 設計の原則

- **バッファの中身は常に UTF-8 で、行の区切りは LF です。** tree-sitter、LSP、フォーマッタ、検索はすべてこの表現を前提にしています。変換はファイルの入出力の境界（Load / Reload / LoadFrom / Save）だけで行います。
- **保存時には、読み込んだときの形に戻します。** 文字コード、BOM、NFD、改行コードを記憶しておき、書き出すときに復元します。
- **戻せないものは書きません。** 変換のたびに逆変換して元のバイト列と一致するかを確認します。一致しなければ「lossy」とみなし、バッファを読み取り専用にして保存を拒否します。
- **黙って置き換えません。** 変換できない文字は `?` などに置き換えず、行番号つきのエラーで保存を止めます。

## 読み込みの流れ

```
os.ReadFile ──▶ Prescan ──▶ Decode ──▶ NFC 変換 ──▶ 行に分割（loadText）
 (1 回だけ)   文字コード判定  UTF-8 へ   全体が NFD の     改行コードを数える
              BOM/バイナリ    逆変換で確認  ときだけ
```

1. ファイルは**全体を 1 回だけ**読みます。先頭だけを見る方式ではないので、先頭の 64KB が ASCII でも、後ろに Shift_JIS があれば正しく判定されます。判定と読み込みの間にファイルが変わることもありません。
2. `Prescan` が文字コード、BOM、バイナリかどうかを判定します。
3. `Decode` が UTF-8 に変換します。変換結果を同じ文字コードで書き戻し、元のバイト列と一致すれば lossless です。
4. UTF-8 でファイル全体が NFD のときだけ、NFC に変換します（後述）。
5. `loadText` が行に分割し、改行コードを数えます。改行は変換後の UTF-8 に対して数えるので、UTF-16 でも正しく判定できます。

## Prescan の判定順序

| 順 | 条件 | 結果 |
|---|---|---|
| 1 | 空ファイル | UTF-8 |
| 2 | `EF BB BF` で始まる | UTF-8 BOM |
| 3 | `FF FE` / `FE FF` で始まる | UTF-16LE / UTF-16BE（BOM あり） |
| 4 | NUL バイトを含む | BOM なしの UTF-16（ASCII 主体で、NUL が偶数または奇数位置に偏っている）、そうでなければバイナリ |
| 5 | 7bit のみで `ESC $ B` / `ESC $ @` を含む | ISO-2022-JP（UTF-8 として有効なバイト列なので、先に判定する） |
| 6 | UTF-8 として有効 | UTF-8（ASCII のみのファイルもここ） |
| 7 | 上記以外 | CP932 と EUC-JP を試し、逆変換で一致したものを採用 |
| 8 | どれも一致しない | lossy（UTF-8 に U+FFFD を入れて表示。読み取り専用） |

手順 7 で CP932 と EUC-JP の両方が一致した場合は、日本語として自然な方を選びます。かな・漢字が多いほど加点し、半角カナ、U+FFFD、私用領域、制御文字は減点します。同点なら CP932 です。

BOM なしの UTF-16 は、ASCII を含まない日本語だけのファイルでは NUL がなく、判定できません。その場合は `reload-encoding` で指定します。

読み込み後のテキストに NUL が残っているファイル（UTF-32 や実行ファイルなど）も、バイナリとして扱います。

## 対応する文字コード

`ESC x encoding` などで指定できる名前です（大文字小文字、`-`、`_`、空白は無視されます）。

| 名前 | 別名 |
|---|---|
| `UTF-8` | `utf8` |
| `UTF-8-BOM` | `utf8bom` |
| `UTF-16LE` / `UTF-16LE-BOM` | `utf16`（= UTF-16LE BOM あり） |
| `UTF-16BE` / `UTF-16BE-BOM` | |
| `CP932` | `ms932`, `windows31j`, `sjis`, `shiftjis` |
| `EUC-JP` | `eucjp` |
| `ISO-2022-JP` | `iso2022jp`, `jis` |

UTF-16、EUC-JP、ISO-2022-JP は `golang.org/x/text` を使います。CP932 は自前のテーブルです。

## CP932

`x/text` の Shift_JIS は JIS X 0208 だけで、Windows が使う NEC / IBM 拡張（① ㈱ 髙 など）を持ちません。そのため CP932 は `cp932_table.go` のテーブルで実装しています。

- テーブルは Python の `cp932` コーデックから生成したもの（double byte 9,604 コード）で、手で編集しません。
- 0x5C と 0x7E は ASCII の `\` と `~` です（JIS X 0201 の `¥` と `‾` ではありません）。
- 同じ文字に複数のコードがある場合、**書き出し時**は Windows と同じ優先順位で選びます。

  | 優先 | 区画 | 例 |
  |---|---|---|
  | 1 | JIS X 0208（第 1・第 2 水準） | ∵ → `81E6` |
  | 2 | NEC 13 区（`87xx`） | ㈱ → `878A` |
  | 3 | IBM 拡張（`FA`〜`FC`） | 髙 → `FBFC` |
  | 4 | NEC 選定 IBM 拡張（`ED` `EE`） | |

- 半角カナ（`A1`〜`DF`）は U+FF61〜U+FF9F です。

### 制限

- **NEC 選定 IBM 拡張（`ED`/`EE` 行）の漢字を含むファイルは lossy になります。** 読み込むと文字は正しく読めますが、書き戻すと `FA`〜`FC` 行のコードになり、元のバイト列と一致しないためです。
- **`〜`（U+301C）、`‖`（U+2016）、`−`（U+2212）などは保存できません。** CP932 には `～`（U+FF5E）などが正規の文字として割り当てられています。Windows や Python はこれらを黙って置き換えますが、ge は置き換えず、行番号つきのエラーにします。

## UTF-8-mac（NFD）

macOS が作る、濁点・半濁点などが分解された形（NFD）のテキストです。

- **ファイル全体が NFD のときだけ** NFC に変換します。条件は次の 3 つです。
  1. ファイルが NFD である
  2. NFC にすると変わる部分がある
  3. NFC に変換して NFD に戻すと、元と完全に一致する
- NFC と NFD が混在するファイルは変換しません。変換すると、触っていない行まで書き換わって差分が大きくなるためです。
- 変換した場合は、保存時に NFD へ戻します。編集中に NFC で入力した文字も、保存時に NFD になります。
- 対象は UTF-8（BOM の有無は問わない）だけです。UTF-8 以外の文字コードへ `encoding` で変更すると、NFD での保存は行われなくなります。

## 保存の流れ

```
行を LF で連結 ──▶ NFD に戻す ──▶ LF を元の改行に置換 ──▶ エンコード ──▶ BOM を付加 ──▶ 書き込み
 (eb.Bytes())     （NFD で読んだ     （CRLF / CR）          （失敗したらここで         
                   ときだけ）                                 エラー）
```

- 変換は**ファイルに触る前**に完了します。変換できない文字があっても、既存のファイルは変更されません。
- エンコードに失敗したときは、`line 3: U+1F600 (😀) cannot be written as CP932` のようにエラーが出ます。行番号は、保存先の改行で数えた行です。
- lossy のバッファは `ErrLossy` で保存を拒否します。

## 改行コード

- 読み込み時に、LF / CRLF / CR の数を数え、**最も多いもの**をそのバッファの改行コードにします。
- 3 種類のうち複数が混在している場合は、最も多い改行コードに揃え、読み込み結果に「Mixed newlines unified」と記録します。行ごとの改行コードは保持しません。
- 保存時は、そのバッファの改行コードで書き出します。

## ESC x コマンド

| コマンド | 動作 |
|---|---|
| `encoding NAME` | **保存時の**文字コードを変更します。バッファの内容は変わりません。変更するとバッファは modified（`**`）になります。 |
| `reload-encoding NAME` | 指定した文字コードで**ファイルを読み直します**。自動判定が外れたときに使います。 |
| `newline lf\|crlf\|cr` | **保存時の**改行コードを変更します。変更するとバッファは modified になります。 |

- `encoding NAME` は、変更する前に現在の内容を指定の文字コードで変換できるか確認します。変換できない文字があれば、その行番号を表示して変更しません。
- `reload-encoding NAME` は、未保存の変更があると拒否します（保存するか、`reload-file` で破棄してください）。指定の文字コードで損失なく読めない場合でも、内容は表示しますが、読み取り専用（lossy）になります。
- lossy のバッファに `encoding` を実行しても拒否されます。先に `reload-encoding` で読み直してください。
- `newline` は `unix`（= `lf`）、`dos` / `windows`（= `crlf`）、`mac`（= `cr`）も受け付けます。
- 引数は Tab で候補から選べます。

### 使い方の例

```
ESC x reload-encoding euc-jp    判定が外れた EUC-JP のファイルを読み直す
ESC x encoding utf-8            保存時に UTF-8 へ変換する（C-x C-s で保存）
ESC x newline lf                CRLF のファイルを LF にして保存する
```

## モードラインの表示

モードラインには、文字コードと改行コードが `CP932 CRLF` のように表示されます。

| 表示 | 意味 |
|---|---|
| `UTF-8` / `UTF-8-BOM` / `UTF-16LE-BOM` / `CP932` / `EUC-JP` / `ISO-2022-JP` | 保存時の文字コード |
| `-mac` が付く（`UTF-8-mac`） | NFD で読み込み、保存時に NFD へ戻す |
| `!` が付く（`CP932!`） | 損失なく読めなかったファイル。読み取り専用で、保存できない |

## ファイルを直接読む他のコード

バッファに読み込まれていないファイルを読むコードは、`os.ReadFile` ではなく `charset.ReadFile` を使います。バッファが持つ内容と同じ形（UTF-8、NFC）で読めるためです。

- `lsp-rename-symbol`（バッファとの比較、編集の検証、プレビュー）
- mark 一覧のテキスト表示

`os.ReadFile` で読んだバイト列を LSP の位置と突き合わせると、UTF-8 以外のファイルでずれます。

## API

| 関数・型 | 役割 |
|---|---|
| `Prescan(raw) Info` | 文字コード、BOM、バイナリ、lossy かどうかを判定する |
| `Decode(raw, spec) (text, lossless)` | UTF-8 へ変換する。`lossless` は逆変換で一致したか |
| `Encode(text, spec, macNFD, nl) ([]byte, error)` | 保存用のバイト列を作る。失敗は `*EncodeError`（行番号つき） |
| `Open(raw) File` / `OpenAs(raw, spec) File` | Prescan（または指定）から NFC 変換までをまとめて行う |
| `ReadFile(path) (File, error)` | ファイルを読んで `Open` する |
| `ParseSpec(name)` / `SpecNames()` | 名前の解釈と、補完用の名前の一覧 |
| `IsMacNFD(text)` / `ToNFC` / `ToNFD` | NFD の判定と変換 |

`EditBuffer` 側の主な API:

| メソッド | 役割 |
|---|---|
| `GetEncoding()` | モードライン用の名前 |
| `EncodingSpec()` / `SetEncoding(spec)` | 保存時の文字コードの取得・設定 |
| `SetNewline(nt)` | 保存時の改行コードの設定 |
| `CheckEncoding(spec)` | 現在の内容を指定の文字コードで保存できるか確認する |
| `ReloadAs(spec)` | 指定の文字コードで読み直す |
| `IsLossy()` | 損失なく読めなかったか（`IsReadonly()` も true になる） |
| `LoadResult()` | 読み込み時に行った変換と警告（`Result` のビット） |

`SetEncoding` と `SetNewline` は undo 履歴を変えないため、`IsDirtyFlag()` は undo スタックに加えて、これらの変更も見ます。保存すると解除されます。

## 既知の事項

- 起動時に開くファイルの読み込み結果（混在した改行の統一や lossy）は、echo では通知されません。モードラインの表示で確認してください。`reload-file` と `reload-encoding` の後には通知されます。
- ファイル全体をメモリに読み込んでから変換するため、巨大なファイルでは一時的にファイルサイズの数倍のメモリを使います。
- `utils/prescan` はこのパッケージとは別物で、現在の読み込み経路では使っていません。
